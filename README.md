# 成为传奇 · Become a Legend

一个纯前端的像素风足球生涯模拟游戏。你扮演一名 17 岁的青训球员，通过每周的安排与一场场比赛，
从无名少年成长为世界足球先生。

**核心玩法**：比赛中会随机出现「高光时刻」（射门 / 传球 / 盘带 / 防守），
你需要用鼠标或手指**在球场上划出一条轨迹**来完成这次操作。
轨迹的**终点、形状、长度**都会被判定，而你的能力值直接决定容错圈大小、划动时间与对手的抢断范围。

## 操作说明

**射门 / 传球是两段式操作：**

1. **划方向** —— 从球出发划一下，**只取方向**（划多长、多快都不影响判定）。
2. **点触球点** —— 画面切到球的近景。球会原地跳 / 横向滚动 / 斜向移动 / 静止，速度随机。
   点击球上的某个位置，**离球心越远**：弧线越大、球飞得越高、也越难控制（精度惩罚越大）。
3. **飞行** —— 按「方向 + 弧线 + 高度」模拟真实弹道。

> 门将只会按你**出脚那一瞬间的直线方向**预判扑救，所以弧线才能真正骗过他；
> 防守球员只能封堵**低平球**，把球搓起来就能从他们头上过去 —— 但触球点太靠边会打高。

| 场景 | 你要做的 | 判定 |
| --- | --- | --- |
| **射门** | 划方向 → 点触球点（弧线绕过门将） | 是否打正 / 打高（超过横梁）/ 被防守球员封堵 / 被门将扑出 |
| **传球** | 划方向 → 点触球点（弧线绕开防守） | 球滚动过程中是否从防守球员脚下穿过、是否滚到队友脚下 |
| **盘带** | 划出跑动路线，绕开红色抢断圈，终点落在黄色区域 | 沿轨迹实时推进并检测碰撞 |
| **防守** | 划出拦截路线，在对手前进路线（黄色虚线预览）上截住他 | 你的跑速与对手跑速的时空交汇点 |

- 起手必须**靠近球**（球上会有一个脉冲光圈提示）。
- 每种场景都有**限时**（触球点那一阶段更短，因为球在动）。
- 结果分为 **精彩 / 成功 / 失败** 三档，直接影响赛后评分与本场成长。

## 系统

**属性（6 项）**：射门 / 传球 / 盘带 / 防守 / 速度 / 体能，1–99。
综合评分按位置加权（7 个位置：中锋、边锋、前腰、中前卫、后腰、边后卫、中后卫）。

**能力值如何影响操作难度**
- 射门：容错圈更大、门将判断正确率更低、扑救范围更小
- 传球：终点容错与路线容错更大
- 盘带：对手抢断圈更小
- 防守：拦截范围更大、对手跑动路线的预览更远
- 速度：划动时间更充裕、盘带/防守时移动更快
- 体能：体力消耗更慢，并计入实际发挥值

体力、士气、状态、队内关系都会修正「实际发挥值」，实际的对手强度决定场景难度。

**一个赛季**
1. 每周选择一个安排：6 种属性特训 / 休息 / 队友聚会 / 商业活动
2. 随机触发决策事件（更衣室风波、赞助商、带伤出战、经纪人施压……）
3. 第 3–4 步：赛前预测 → 比赛（亲手操作，或快速模拟）→ 赛后评分与成长
4. 赛季末：名次、个人荣誉（最佳射手 / 助攻王 / MVP / 最佳新人 / 世界足球先生）、属性成长、转会报价
5. 年龄 +1，进入下赛季；36 岁退役，生成生涯履历

**其他**：联赛积分榜与双循环赛程、伤病与伤停、身价/周薪、投资商店（私人教练 / 康复师 / 公关团队 / 定制战靴）、localStorage 自动存档。

### 相机与坐标
世界坐标固定为 256×160，相机只显示右侧进攻区域（`P.VX=56, P.VY=18`，视野 200×124）。
游戏逻辑全部写在世界坐标里，绘制时每帧统一做两次 `setTransform`：

- **世界层**：`(SCALE, 0, 0, SCALE, -VX*SCALE, -VY*SCALE)`
- **UI 层**（计时条 / 结算横幅 / 底部提示）：`(SCALE, 0, 0, SCALE, 0, 0)`，继续用 200×124 坐标

`P.SCALE = 2` 表示画布实际像素为 400×248：世界坐标和操作判定完全不变，
只是采样密度翻倍 —— 像素块更细、线条和文字更清晰。
`P.rect()` 会把坐标吸附到 `1/SCALE`（半个单位 = 1 个画布像素），
所以画细节时既能有半单位精度，又不会出现半像素导致的模糊。
输入换算始终是「CSS 像素 → 视野单位 → 世界坐标」，与 SCALE 无关。

## 版本

界面上有两处版本号，用来确认自己玩的是不是最新部署：

- **主菜单标题下方**：`版本 vX.Y.Z · 日期`
- **右下角常驻**：`vX.Y.Z`，点它可以打开版本信息并**检查更新**

启动时会静默 `fetch('version.json')` 比对线上版本，发现更新会在顶部挂一条「发现新版本」横条，点一下强制刷新。

改版本号请用脚本，它会同步三处，避免「界面上显示的版本」和「实际加载的资源」对不上：

```bash
node tools/bump.js 0.6.0 "这次改了什么"
```

会更新 `src/data.js` 的 `BL.VERSION`、`version.json`、以及 `index.html` 里全部 `?v=` 参数。
`?v=` 是**缓存击穿**：版本一变资源 URL 就变，绕过 GitHub Pages 的 CDN 缓存
（否则你刷新了，浏览器可能还是拿旧的 JS/CSS，看起来像"没更新"）。

## 部署到 GitHub Pages

这个项目是**纯静态**的，可以直接用 Pages 托管（已验证：无构建步骤、无 ES module、
无外部 CDN / 字体 / 图片、所有引用都是相对路径、文件名大小写与引用完全一致）。

```bash
git init
git add .
git commit -m "成为传奇：像素风足球生涯模拟"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

然后在仓库页面：**Settings → Pages → Build and deployment**
- Source 选 `Deploy from a branch`
- Branch 选 `main`，目录选 `/ (root)`
- 保存后等 1 分钟左右，访问 `https://<你的用户名>.github.io/<仓库名>/`

仓库根目录已经放了 `.nojekyll`，跳过 Jekyll 处理，构建更快也不会漏文件。

**注意**
- 存档在 localStorage，作用域是 origin。在 Pages 上所有项目共享 `<用户名>.github.io`，
  所以存档 key 会自动带上部署路径后缀做隔离；本地 `file://` 打开时仍用原始 key。
- 通过 Pages 访问时可以用 `#dev=hub` 之类的调试入口，调试模式**不会写入存档**。
- 想用自定义域名或改成 `<用户名>.github.io` 根仓库部署都没问题，相对路径不依赖子目录。

## 自检

```
node tools/selftest.js
```

用假的 canvas 上下文加载全部脚本，做三件事：
1. 320 次场景结算（4 种场景 × 4 档难度 × 4 档能力 × 5 种划动方式），检查异常与结算
2. 对比「认真划」与「乱划」的成功率，验证操作技巧确实影响结果
3. 6 个位置各跑 3 个赛季的完整生涯（含训练、事件、比赛、转会、赛季结算、界面渲染）
